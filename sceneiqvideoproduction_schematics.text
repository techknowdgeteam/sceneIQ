SCENEIQ VIDEO PRODUCTION — ENGINE SCHEMATICS
============================================

Document purpose
----------------
This document describes the video-production engine in the uploaded
sceneiqvideoproduction.py script. It explains where the engine gets a project,
how it interprets script scenes and their metadata, what files it expects,
how it uses narration and images, and how it builds and publishes the MP4.

This describes the uploaded implementation. SceneIQ Video Production is an
independent renderer/queue. It does not import, launch or operate Google Flow.

1. WHAT THIS ENGINE DOES
------------------------
SceneIQ Video Production converts one completed SceneIQ image project into a
narrated video. In broad terms it:

  1. Reads completed project records from ready_script.json.
  2. Identifies a project by its title/category and finds its scene script.
  3. Locates the corresponding project folder and numbered entry_N images.
  4. Finds the matching narration audio file (normally in Downloads).
  5. Reads each scene's timing and optional editing instructions.
  6. Uses Faster-Whisper when word timing is needed for captions or instructional
     headings.
  7. Fits each image to the video frame, then applies the scene's explicit
     camera movement, transition, video effects, captions, overlays and stickers.
  8. Renders each scene to an intermediate video segment.
  9. Concatenates scene segments and muxes the narration audio using FFmpeg.
 10. Validates the completed MP4, preserves any previous output as a backup and
     publishes the new video in the project's edited folder.

It does NOT create the scene images. It consumes images already generated by
SceneIQ Image Production (or otherwise placed in the expected project folder).

2. ENGINE BOUNDARIES AND PATHS
------------------------------
Main paths declared in the uploaded script:

  PANEL_PATH          C:\xampp\htdocs\AI automation\scenIQ\panel.json
  READY_SCRIPT        C:\xampp\htdocs\AI automation\scenIQ\ready_script.json
  IMAGES_PATH         C:\xampp\htdocs\AI automation\scenIQ\project
  SUBSCRIBE_STICKERS  C:\xampp\htdocs\AI automation\scenIQ\subscribe

The completed project reader uses READY_SCRIPT as its project/script source.
The renderer finds images under IMAGES_PATH and subscribe animations under
SUBSCRIBE_STICKERS. The service also watches the Downloads folder for new audio
and the project tree for late-arriving images.

The script uses MoviePy 2.x, Pillow, NumPy, FFmpeg/imageio-ffmpeg and Faster-
Whisper where speech recognition is required. It supports CPU encoding through
libx264 and can use NVIDIA NVENC when a suitable GPU/encoder is available.
The worker and dashboard infrastructure is part of the same file.

3. PROJECT INPUT: ready_script.json
-----------------------------------
The image engine writes completed project snapshots to ready_script.json. The
video engine accepts several outer container shapes:

  A JSON list of project records:
    [ {project record}, {project record} ]

  An object with a projects list:
    {"projects": [ {project record}, {project record} ]}

  A legacy single-project object:
    {project record fields...}

  Nested wrappers:
    {"value": {project record}}
    or other object/list nesting containing project records.

The reader recursively searches for project records. A discoverable project
needs a title and a non-empty script dictionary/list. Duplicate projects are
removed using normalised category + title identity.

3.1 Project-level fields

  automation.project_title
  automation.project_name
  project_title / project_name / projectTitle / projectName
      Identifies the project and locates its image folder. Use project_title.

  automation.project_category
  project_category / projectcategory / projectCategory
      Optional category parent folder. It must correspond to the image project's
      category when possible.

  script (sometimes inside script_json)
      Must resolve to a non-empty object/list containing scene entries.

  include_captions
      Captions are enabled only when the value resolves to the text "yes"
      (case-insensitive, surrounding whitespace ignored). Use exactly "yes" to
      enable. A JSON boolean true is not equivalent to the string "yes" here.

  include_transitions
      Project-level master switch. Missing means transitions are allowed. Values
      no, false, 0, off or disabled globally disable transitions. The individual
      scene transition_to_next field still controls which boundary is affected.

  instructional_overlay_theme / stage_overlay_theme / overlay_theme
      Optional project-level overlay palette/theme. When supplied, this global
      theme controls the generated heading palette rather than trusting scene-
      level colours independently.

3.2 Recommended scene structure

Each ordered scene is a JSON object in the project's script list. The same
project record that contains the image prompts can retain video-specific fields:

{
  "automation": {
    "project_title": "Example Project",
    "project_category": "Documentary"
  },
  "include_captions": "yes",
  "include_transitions": "yes",
  "script": [
    {
      "shot_number": 1,
      "characters_reference": "Recurring character visual reference ...",
      "scene_Image_generation": "The visual scene description ...",
      "dialogue": "The spoken words for this scene ...",
      "start": "00:00",
      "stop": "00:05",
      "transition_to_next": {
        "apply": true,
        "type": "crossfade",
        "duration_seconds": 0.35
      },
      "keyframes": {
        "enabled": true,
        "sequence": ["pan_left", "zoom_in"],
        "zoom_mode": "sequential"
      },
      "video_effects": {
        "enabled": true,
        "effects": [
          {"type": "film_grain", "intensity": 0.25}
        ],
        "start_offset_seconds": 0,
        "duration_seconds": 3
      },
      "instructional_overlay": {
        "enabled": true,
        "category": "step",
        "identifier": "1",
        "display_text": "The first step",
        "pre_roll_seconds": 0.65,
        "entrance_effect": "slam_in",
        "hold_seconds": 0.65,
        "exit_effect": "fade_out"
      }
    },
    {
      "shot_number": 2,
      "characters_reference": "Same recurring character reference ...",
      "scene_Image_generation": "The next visual scene ...",
      "dialogue": "The next spoken words ...",
      "start": "00:05",
      "stop": "00:10"
    }
  ]
}

The sample is a schematic: optional editing fields can be omitted. A scene is
recognised through any of several marker keys such as scene_pov_prompt,
scene_Image_generation, characters_reference, shot_number, dialogue, narration,
voiceover, spoken_text, instructional_overlay, stage_overlay, video_effects or
caption metadata. Older nested batches with an "entries" array are also read.
Use one scene object per image and keep the scene list in intended storyboard
order.

4. HOW THE VIDEO ENGINE MATCHES DATA
-----------------------------------

A. Project record -> image folder
   - Reads project title/category from ready_script.json.
   - Resolves the preferred folder:
       project/<category>/<project_title>/
   - Recognises historical flat and Uncategorized layouts as fallbacks.
   - Avoids arbitrary selection if category-less metadata matches multiple
     project folders ambiguously.

B. Script scenes -> image files
   - Recursively discovers scene dictionaries in the script.
   - Supports the newer scene-by-scene list and older nested "entries" lists.
   - Collects scenes in traversal/list order, removing duplicate references to
     the same dictionary.
   - Sorts available image files by the numeric suffix in entry_N.
   - Pairs scene 1 with entry_1, scene 2 with entry_2, and so on.

   shot_number is a scene marker/metadata field; it does not independently
   remap image filenames. The actual pairing relies on scene order and entry
   number. Keep the image producer's script order and the video script order
   aligned. Do not reorder scenes without also renumbering/replacing entry_N.

C. Preflight
   - Confirms the resolved project folder and usable scene images.
   - Checks expected entry numbers and skips a project if required images are
     missing or invalid.
   - Creates edited and (when captions are enabled) temp_captions folders.
   - Moves/copies the thumbnail into edited/Thumbnail.png when it finds one.
     A missing thumbnail is a warning, not a blocker for video rendering.

Video image enumeration currently includes PNG, JPG/JPEG, GIF, BMP and WEBP.
Although some earlier validation checks also recognise TIFF, the actual sorted
image collection used for rendering excludes TIFF. Use PNG/JPG/WEBP for scene
images to avoid this mismatch.

5. NARRATION AUDIO INPUT AND WORD TIMING
----------------------------------------
The normal queue does not read an audio path from a project JSON field. It
searches the user's Windows Downloads folder for a valid audio file whose name
matches the project title after normalising punctuation, spacing and case. It
supports common audio formats including MP3, WAV, M4A, AAC, OGG, FLAC and WMA.
When multiple matching files exist, the newest valid matching file is selected.
If no matching narration file is found, the project is skipped. The lower-level
process_single_video function can also receive an explicit audio_path argument
when invoked directly; this is not the normal READY_SCRIPT JSON contract.

Faster-Whisper is used to transcribe the narration into word-level timestamps
when ordinary captions are enabled or dynamic instructional headings need to
be matched to spoken words. The default model is "small"; device and compute
type are controlled by worker/environment settings (CPU defaults to int8,
GPU normally uses float16). Recognition can use a cached timestamp file when
the audio and model/device signature have not changed.

Important distinction:

  - The narration audio file is the source of the final video's audio track.
  - The audio transcription provides the timing/content for normal animated
    captions and speech-synchronised instructional headings.
  - The per-scene dialogue/narration fields help identify scene text and CTA
    phrases, but they are not a substitute for the narration audio file.
  - Normal captions are ASR-word-timed; the engine does not simply paint each
    scene's dialogue string as a static subtitle line.

If include_captions is "yes" but transcription does not provide usable words,
the captioned project can fail preflight/render. If ordinary captions are off
but instructional overlays need speech timing, ASR may still run for overlays.

6. SCENE TIMING AND VIDEO LENGTH
--------------------------------
The parser recognises these timing fields on a scene:

  start / start_time / scene_start
  stop / end / stop_time / scene_end
  duration / duration_seconds / scene_duration

String timestamps are interpreted as MM:SS or HH:MM:SS. Explicit duration
values are interpreted as seconds. When no usable timing is supplied, the
scene starts at the running cursor and receives a five-second fallback. When a
valid stop is later than start, duration is stop minus start. Otherwise a
positive explicit duration is used.

The parsed scenes are sorted by start time. The scene timing controls how long
the corresponding still image is visible and when scene-specific camera,
effects, captions/overlays and transition operations are applied. The output
frame rate is 24 frames per second and output dimensions are fixed at 1920 x
1080 (16:9).

The engine checks the narration duration. Where possible it extends or shortens
the final image duration so the video ends with the narration. If preceding
scene timings already exceed the audio duration, it fits the preceding scenes
into the available time while preserving the final image through the audio end.

7. SCENE EDITING METADATA — WHAT EACH FIELD MEANS
------------------------------------------------
These are explicit editing instructions, not free-form prose that the renderer
tries to interpret creatively. Use the supported names and values below.

7.1 transition_to_next

This field belongs to the scene that is ending. It describes the boundary from
that scene to the following scene. It does not set an entrance effect for the
current scene. It may be a string or an object with fields such as type,
transition_type, effect, name, keyword, keywords, label, apply/enabled,
duration_seconds/duration/transition_duration and reason.

Supported transition types:

  none        Direct cut/no transition.
  crossfade    Blend outgoing and incoming scenes.
  wipe_left    Wipe toward the left.
  wipe_right   Wipe toward the right.
  slide_left   Slide toward the left.
  slide_right  Slide toward the right.

The project-level include_transitions switch can disable all transitions. The
renderer bounds transition duration (up to 2 seconds and a fraction of the
adjacent scene durations). Unknown transition values are not a request for a
new effect; they fall back to a safe direct cut.

Example:
  "transition_to_next": {
    "apply": true,
    "type": "wipe_left",
    "duration_seconds": 0.4,
    "reason": "Move into the next location"
  }

7.2 keyframes

This controls camera-like movement over the still image. It can be a short
string/variation or an object. The object may include enabled, static,
variation_id/id/variation/variation_keyword/camera_movement, sequence/actions/
camera_actions/action_sequence, keywords, zoom_mode, end_position, reason,
label and group.

Supported motion actions are:

  pan_left
  pan_right
  pan_center
  zoom_in
  pan_center_zoom_out

The sequence is limited to three actions. Supported zoom modes are:

  hold, zoom_only, sequential, sequential_reset,
  concurrent_in, concurrent_in_soft, in_out

Use an explicit sequence when a scene needs movement. Missing, disabled,
empty or invalid sequences resolve to a static image instead of invented
camera movement. Example:

  "keyframes": {
    "enabled": true,
    "sequence": ["pan_right", "zoom_in"],
    "zoom_mode": "sequential",
    "end_position": "right",
    "reason": "Reveal the room"
  }

7.3 video_effects / video_effect

Adds one or more effects to the scene footage. The input may be a string, list
or object. An object can contain enabled, effects/effect/keywords, intensity,
start_offset_seconds and duration_seconds. Each effect item can be a string or
an object with type/name/effect and intensity. Default intensity is 0.5 and is
bounded by the implementation.

Supported effects:

  black_white, sepia, vintage, archival, cctv, film_grain,
  scanlines, vignette, glitch, shake, flicker, blur,
  high_contrast, desaturate, cold_tone, warm_tone

Some aliases are normalised (for example black_and_white -> black_white,
grains/noise-style labels to film_grain, camera_shake -> shake and VHS/digital
glitch aliases to glitch). Unsupported effects are ignored with a warning.
The effects are applied to the scene footage, not to caption/heading text.

Example:
  "video_effects": {
    "enabled": true,
    "effects": [
      {"type": "archival", "intensity": 0.35},
      {"type": "film_grain", "intensity": 0.2}
    ],
    "start_offset_seconds": 0.5,
    "duration_seconds": 3.0
  }

7.4 instructional_overlay / stage_overlay

Creates a temporary instructional heading/interstitial such as Stage 1, Step 2,
Level 3, Example 1 or Chapter 4. It may be an object for one overlay or a list
of objects for multiple overlays. Each object supports:

  enabled                  Whether this heading is active (default enabled).
  category                 stage / step / level / example / chapter.
  identifier or number     Identifier shown in the default heading.
  display_text             Actual heading text; aliases heading or title work.
  background_color         Background colour (alias background).
  text_color               Heading text colour.
  pre_roll_seconds         Lead-in before the detected speech phrase (default
                           0.65 seconds).
  entrance_effect          How the heading enters (default slam_in).
  entrance_duration_seconds (default 0.38 seconds).
  emphasis_effect          Optional emphasis (default none).
  emphasis_duration_seconds (default 0.30 seconds).
  hold_seconds             Hold duration (default 0.65 seconds).
  exit_effect              Exit animation (default fade_out).
  exit_duration_seconds    Exit duration (default 0.24 seconds).
  keep_until_scene_end     Keep the heading displayed to the scene end.

Example:
  "instructional_overlay": {
    "enabled": true,
    "category": "chapter",
    "identifier": "2",
    "display_text": "The Investigation",
    "pre_roll_seconds": 0.65,
    "entrance_effect": "slam_in",
    "hold_seconds": 0.8,
    "exit_effect": "fade_out"
  }

Overlay timing is tied to words recognised in the narration. The engine can
also read legacy flat fields such as stage_1_involved, step_2_involved,
level_3_involved, example_1_involved or chapter_4_involved and their associated
heading/style fields. When an overlay is visible it occupies the instructional
interstitial layer; ordinary bottom captions are suppressed for the heading
words while that heading is displayed. Overlays can still require ASR even if
ordinary captions are turned off. A project-level overlay theme can control the
palette globally.

7.5 Caption animation fields

Per-scene caption_animation and caption_effect styling metadata is deliberately
ignored by the current renderer. The function returns the locked legacy ASR-
synchronised, single-row typewriter caption style. Project caption defaults do
not override this locked behavior. To enable ordinary captions, set the
project-level include_captions value to the text "yes".

7.6 Dialogue and subscribe sticker trigger

Scene text lookup checks dialogue, narration, voiceover, voice_over,
voice_over_script, spoken_text, caption, subtitle and text. The source dialogue
is also inspected for phrases such as "LIKE AND SUBSCRIBE" or "SUBSCRIBE".
When a trigger is present, the engine may place an animated subscribe sticker
from the subscribe folder. The sticker folder expects animated transparent GIF,
WEBP or APNG assets; static images are not accepted by the animation loader.
The sticker is displayed at the established 50% scale and centered; the logic
starts it at the scene start and removes it shortly before the scene ends. If
there is no valid sticker asset, no sticker is shown. Sticker behavior is not
simply the same setting as ordinary captions.

8. HOW THE VIDEO IS ACTUALLY BUILT
----------------------------------

A. Preflight and asset pairing
   - Parse READY_SCRIPT and choose an eligible project.
   - Resolve the project image directory.
   - Sort entry_N images numerically.
   - Verify required images are present, non-empty and readable.
   - Find the narration audio file.
   - Create edited/ and any caption temporary folders.

B. Prepare audio and optional transcript
   - Open/probe the narration audio and determine its duration.
   - If captions or instructional headings need speech alignment, run/reuse
     Faster-Whisper word-level recognition.
   - De-duplicate repeated word events only when their timestamps overlap.
   - Keep the original narration audio as the final soundtrack.

C. Prepare each scene image
   - Open the matching entry_N file.
   - Convert it to RGB, centre-crop to 16:9 and resize to 1920 x 1080.
   - This is a centre crop, not letterboxing; some outer image area can be cut.
   - Load the scene duration, keyframe plan, transition plan, video effect plan,
     instructional overlay and relevant narration/CTA data.
   - The source image file remains unchanged.

D. Render the scene frame by frame
   - MoviePy requests frames at 24fps.
   - The renderer derives per-frame camera movement from the explicit keyframe
     plan (pan/zoom) or holds the image static.
   - The configured footage effects are applied during their active interval.
   - The previous-scene transition plan is applied at the scene boundary.
   - ASR-timed captions, dynamic instructional headings and any subscribe
     sticker are composed in their respective layers.
   - Captions/overlays are not baked into or written back to the source image.

E. Encode intermediate scene segments
   - Render each scene as a separate temporary video segment.
   - Validate it and atomically save the segment to the checkpoint directory.
   - Record completed scene numbers and progress so a later run can reuse
     already completed segments when the render fingerprint still matches.
   - If project inputs/settings/audio/images change, the fingerprint changes
     and old scene segments are invalidated rather than silently reused.

F. Assemble the final video
   - Build an FFmpeg concat list in scene order.
   - Concatenate scene segments without re-encoding the video stream where
     possible and add the original narration audio track.
   - Encode audio as AAC at 320k and cap the output to the calculated duration.
   - Validate the temporary MP4 before publishing.
   - If a previous final MP4 exists, rename it to <title>_old_N.mp4.
   - Atomically move the new final MP4 into the edited folder.

9. OUTPUTS AND DIRECTORY LAYOUT
-------------------------------
Typical project layout:

  project/<category>/<project_title>/
      entry_1.png
      entry_2.png
      entry_3.png
      Thumbnail.png              (optional source thumbnail)
      edited/
          Thumbnail.png          (when a source thumbnail is available)
          <normalised_project_title>.mp4
          <normalised_project_title>_old_1.mp4
          <normalised_project_title>_old_2.mp4
      temp_captions/              (created when captions are enabled)

Other worker/checkpoint data is kept separately, including:

  <READY_SCRIPT directory>/video_producer_checkpoints/<project-hash>/
      progress.json / render_fingerprint.json / render_checkpoint.json
      scene_segments/...
      narration_word_timestamps.json (when ASR cache is used)

  <IMAGES_PATH>/video_producer_runs/...
      Per-run logs and worker artifacts.

The exact temporary worker workspace depends on how the service distributes a
job. The published MP4 target is:

  <project_folder>/edited/<normalised_project_title>.mp4

The source images and original narration are not intentionally overwritten.
Previous final videos are retained as numbered backups.

10. QUEUE, WORKERS, DASHBOARD AND LIVE SERVICE
----------------------------------------------

process_single_video(...)
    Renders one assigned project. It resolves input paths, validates scene
    images and narration, builds captions/overlays/effects, encodes segments,
    assembles the final video and updates worker status/checkpoints. It also
    requests Windows to keep the system/display awake while the worker runs.

_video_producer_collect_ready_titles(ready_script_path)
    Reads READY_SCRIPT, recursively discovers project title/script/category
    records, supports multiple root wrappers and removes duplicate projects.

video_producer_main(...)
    Reads the available project queue, constructs work items and launches
    eligible jobs. It checks resource/GPU availability and assigns CPU/GPU
    worker profiles. The implementation applies a bounded worker count rather
    than starting an unlimited process for every project.

_video_producer_detect_gpu(...)
    Detects usable GPU/encoder capability to decide whether an NVENC lane can
    be used. The CPU path uses libx264.

_video_producer_write_worker_status(...) / _video_producer_read_worker_status(...)
    Write/read per-worker status so the dashboard can display project, stage,
    progress, process, encoder and preview information.

_video_producer_control_checkpoint(...)
    Checks stop/shutdown/control requests at safe checkpoints and updates the
    worker heartbeat/checkpoint state.

_video_producer_prepare_worker_workspace(...)
    Prepares an isolated worker copy/workspace for project inputs and outputs.

_video_producer_process_worker(...)
    Runs a project through its worker process, tracks output files and returns
    the result to the parent process.

_video_producer_execute_jobs_resilient(...)
    Executes the batch of jobs with controlled retry/recovery for worker/resource
    failures, while preserving completed checkpoints.

_video_producer_find_audio_source(title)
    Searches Downloads for the newest valid audio file matching the project
    title.

video_producer_service_loop(...)
    Continuously watches READY_SCRIPT, Downloads and project-directory changes.
    When their input signature changes, it calls video_producer_main() to look
    for newly eligible work. It polls on a short interval (default about two
    seconds) and keeps the producer service independent from Image Production.

SceneIQApp / dashboard helpers
    Provide the producer window, project list, status, previews, controls and
    worker management. The dashboard is the control/monitoring surface; the
    actual rendering occurs in worker processes.

main(...)
    Starts the video producer application/service entry point.

11. RESOURCE MANAGEMENT, CHECKPOINTS AND FAILURE RULES
------------------------------------------------------
The engine renders projects using multiprocessing workers and worker lanes.
CPU lanes use libx264 and CPU Faster-Whisper settings; a GPU lane can use
h264_nvenc when hardware/encoder detection confirms it is available. Worker
limits are bounded by safe CPU/RAM/resource checks.

The worker status contains stage/progress/current/total/detail and paths to logs,
status and preview files. A preview JPG can be refreshed from an actual rendered
scene frame; preview errors are not allowed to fail the video encode itself.
The checkpoint system records project progress and completed scene segments.
The render fingerprint incorporates project/script data, image file signatures,
audio file signature, captions/transitions settings, encoder settings and
render dimensions/frame rate. Changed source data invalidates stale segments.

A project can be skipped when the script is missing/empty, its corresponding
project folder cannot be identified, scene images are missing/invalid, narration
audio is not found/valid, or required caption data cannot be obtained when
captions are mandatory. Failure of one job is reported to the queue; it is not
an instruction to invent missing images, audio or editing metadata.

12. INPUT EXPECTATIONS AND COMMON MISTAKES
-----------------------------------------
For reliable video production:

  - Use the completed project record in READY_SCRIPT, not only an unsaved
    panel.json project that has not been transferred by Image Production.
  - Keep project title/category consistent with the folder path used by the
    Image Producer.
  - Supply one scene record for each intended entry_N image.
  - Keep scene array order aligned with the numbered entry images.
  - Ensure every expected entry image is present and readable.
  - Use a narration audio filename that clearly matches the project title in
    Downloads, or pass audio_path only when calling process_single_video
    directly.
  - Set include_captions to the string "yes" to enable ordinary captions.
  - Use supported transition, keyframe and video-effect values.
  - Supply explicit positive timing values where exact timing is important.
  - Add animated transparent sticker files to the subscribe folder if CTA
    sticker behavior is expected.

Avoid these mistakes:

  1. Expecting the video engine to create missing images. It only consumes them.
  2. Expecting the scene's shot_number to remap entry filenames. Scene/image
     pairing is by collected scene order and numeric entry order.
  3. Setting include_captions to boolean true or string "true". Current code
     specifically checks for the text "yes".
  4. Providing dialogue text but no narration audio. Text alone is not the final
     audio track and is not the source of ordinary ASR-timed caption word timing.
  5. Assuming caption_animation or caption_effect custom values will change the
     current typewriter style. They are ignored by the active caption resolver.
  6. Using unsupported effect/action names and expecting the renderer to invent
     a matching visual effect. Unknown effects are ignored or the scene remains
     static for invalid keyframes.
  7. Using TIFF as a scene image. It may pass one earlier validation but the
     actual render image list does not include TIFF.
  8. Expecting a missing Thumbnail.png to prevent video rendering. The video can
     proceed without a thumbnail; it simply warns and skips thumbnail movement.

14. HOW IT COMMUNICATES WITH IMAGE PRODUCTION
---------------------------------------------
The communication contract is a project snapshot plus files on disk:

  Image Producer creates:
    - project/category/title/entry_N images
    - project/category/title/Thumbnail.png
    - a completed project record appended to ready_script.json

  Video Producer consumes:
    - the record in ready_script.json (title, category and script)
    - entry_N images from the matching project folder
    - a title-matched narration audio file from Downloads
    - optional sticker assets from the subscribe folder

No live Python object or direct function call is shared between the two
production engines. The video producer can discover newly ready work by reading
READY_SCRIPT and monitoring its input signatures. The image producer can finish
and exit before video production starts.

The desktop command deck is a separate control layer: opening the Video
Producer's PRODUCTION view displays the production grid; START PRODUCTION is
